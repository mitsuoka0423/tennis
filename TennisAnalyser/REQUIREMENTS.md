# Requirements Specification: Tennis Swing Analyzer

## 1. プロジェクト概要 (Project Overview)

本プロジェクトは、Apple Watch Series 9（45mm）を利き腕に装着し、テニスにおけるスイング動作のセンサーデータを解析するスタンドアロン型watchOSアプリ、および解析用iOSアプリを開発する。
watchOS 10以降で利用可能な高頻度モーションAPI（`CMBatchedSensorManager` 等）を活用し、最大800Hz（実測値による検証要）のサンプリングによる精密なスイング波形の取得と、オンデバイス（Core ML）でのショット分類を実現する。

---

## 2. アーキテクチャ設計方針 (Architectural Design Principles)

本プロジェクトでは、変更に強く、テスト容易性に優れたコードベースを維持するため、クリーンアーキテクチャ（Clean Architecture）をベースとした明確な関心の分離（Separation of Concerns）を適用する。

```
       ┌────────────────────────────────────────────────────────┐
       │                  Frameworks & Drivers                  │
       │  (Core Motion, HealthKit, WCSession, Core Data, UI)    │
       │                           ▼                            │
       │       ┌────────────────────────────────────────┐       │
       │       │    Interface Adapters (Presenters)     │       │
       │       │  (Gateways, ViewModels, Repositories)  │       │
       │       │                   ▼                    │       │
       │       │   ┌────────────────────────────────┐   │       │
       │       │   │     Use Cases (Interactors)    │   │       │
       │       │   │  (AnalyzeSwing, SyncDevices)   │   │       │
       │       │   │               ▼                │   │       │
       │       │   │      ┌──────────────────┐      │   │       │
       │       │   │      │ Entities (Domain)│      │   │       │
       │       │   │      │  (Swing, Motion) │      │   │       │
       │       │   │      └──────────────────┘      │   │       │
       │       │   └────────────────────────────────┘   │       │
       │       └────────────────────────────────────────┘       │
       └────────────────────────────────────────────────────────┘
```

### 2.1 依存方向ルール (Dependency Rule)

* **内側への単一依存**: 依存関係は常に外側（Frameworks/UI）から内側（Entities/Use Cases）へ向かう。コアなビジネスロジック（Entities/Use Cases）は、UIKit, SwiftUI, Core Motion, HealthKit などの Apple 特有のフレームワークに一切依存してはならない。
* **インターフェースによる境界分離 (Dependency Inversion)**: 外側のコンポーネント（例: センサー、データベース、通信部）は、対応する Use Cases 層が定義したプロトコル（インターフェース）を実装する形で接続する。

### 2.2 テスト容易性（Testability）の重視

* **Core Motion の抽象化**: センサーデータ取得部は `MotionSensorRepository` などのプロトコルで隠蔽する。これにより、テスト実行時にセンサーのダミーデータ（CSVから読み込んだ過去のスイングデータ等）を流し込むモック化を容易にし、実機を振ることなくユースケースおよび解析ロジックの単体テストを可能にする。
* **ロジックの分離**: SwiftUI の View や WatchKit のコントローラーは純粋に描画とユーザー入力のトリガーのみを担当し、スイング検知・ウィンドウ切り出し等のアルゴリズムはビジネスロジックとして完全に分離・独立してテスト可能とする。

## 3. システムコンポーネント構成 (System Components)

### 3.1 Apple Watch側 (watchOS App: Standalone)

* **装着**: 利き腕（右利きであれば右手首）に1台装着する。
* **動作モード**: iPhoneとリアルタイム接続せず、スタンドアロンとしてセンサーデータを記録する。
* **バックグラウンド動作**: `HKWorkoutSession` を起動し、画面消灯時（スイング中）もプロセスサスペンドを防ぎ、センサーサンプリングを継続する。
* **データ永続化**: 取得したデータをタイムスタンプ（ミリ秒精度）付きでローカル（Core DataまたはCSVファイル）に保存する。

### 3.2 iPhone側 (iOS App: Analyzer)

* **データ同期**: ワークアウト終了後、WatchからのバイナリまたはCSVファイルを `WCSession` を介して受信する。
* **可視化と分析**: スイング速度、インパクト時の減速波形、ショット種別の分布などをグラフ表示する。

## 4. 機能要件 (Functional Requirements)

### 4.1 watchOS 側

* **[F-W1] ワークアウトセッション管理**
  * `HealthKit` を使用し、テニスのワークアウトセッションをアクティブ化・非アクティブ化できること。

* **[F-W2] 高頻度センサーデータキャプチャ**
  * `CMBatchedSensorManager` を用いて、加速度（3軸）および角速度（最大4,000度/秒、3軸）を取得すること。
  * サンプリングレートは **200Hz**（`deviceMotionUpdates()` の仕様上限）を採用する。
    * 実機検証（2026-07-17, Series 9）: 実測 ~197Hz を確認。
    * `deviceMotionUpdates()`（200Hz）は加速度・角速度が同期済み・重力除去済み。`accelerometerUpdates()`（800Hz）は加速度のみで、角速度とのペアリング処理が別途必要になるため採用しない（Phase 3 で分類精度が不足した場合に再検討）。
  * ロス率1%未満を維持すること。

* **[F-W3] オンデバイス・ショットフィルタリング & 分類**
  * **1次フィルタ (省電力)**: 加速度ベクトルが一定の閾値（例: $3.0g$）を超えた場合のみ、前後2秒間のウィンドウを切り出して記録対象とする。
  * **2次分類 (Core ML)**: 切り出したウィンドウをCore ML（Action Classificationモデル）に流し、ショット種別（フォアハンド、バックハンド、サーブ、その他）を判定する。
  * Core MLモデルの学習データ収集・アノテーション方針、および精度目標（例: 分類精度90%以上）はPhase 3詳細設計時に定義する（TBD）。

* **[F-W4] ローカル永続化**
  * レコードフォーマット: `[Timestamp (ms), AccX, AccY, AccZ, GyroX, GyroY, GyroZ, ShotClass]`
  * 取得したデータをローカルファイルにバッファリング書き出しすること。

* **[F-W5] バックグラウンドデータ転送**
  * ワークアウト終了時、`WCSession` の `transferFile` を使用して、iPhone側へデータを自動送信すること。

### 4.2 iOS 側

* **[F-I1] Watchデータ受信とハンドリング**
  * `WCSessionDelegate` を実装し、バックグラウンドでのファイル受信、ローカルストレージへの格納を行うこと。

* **[F-I2] 解析エンジン**
  * スイング位相の特徴点（インパクト時刻、スイング速度ピーク、減速開始点等）を検出し、スコアリングすること。
  * スコアリング基準（自己ベスト比較、理論値比較等）はPhase 3詳細設計時に定義する（TBD）。

* **[F-I3] ダッシュボードUI**
  * SwiftUI Charts を用い、加速度・角速度の時系列チャートおよびショット種別の分布を視覚的に表示すること。

## 5. 非機能要件 & 技術的制約 (Non-Functional Requirements & Constraints)

* **対応プラットフォーム (Deployment Target)**:
  * watchOS 10.0以上 (Series 9, 45mm ターゲット)
  * iOS 17.0以上

* **サンプリングレート**:
  * ターゲット: 200Hz（`deviceMotionUpdates()` の仕様上限。実機検証 2026-07-17 で実測 ~197Hz を確認）
  * ロス率: 1% 未満を維持すること

* **バッテリー消費量**:
  * 1時間の連続計測において、Watch単体でのバッテリー消費率を 20% 以下に抑えることを目標とする。
  * 1次フィルタによる不要なCore ML推論の抑制を主な手段とし、Phase 1完了後に実機での消費量を実測して目標値の妥当性を検証すること。

* **ストレージ容量保護**:
  * Watch側はファイル転送完了後にローカルの一時キャッシュデータを自動削除するクリーンアップ機構を設けること。

## 6. 開発ロードマップ & マイルストーン (Milestones)

1. **Phase 1: High-Frequency Data Collector (Watch単体)**
   * ターゲット: `CMBatchedSensorManager` を使用し、200Hzで3軸データを取得してタイムスタンプ付きCSVへ書き出す最小構成の実装。実機にてサンプリングレートとバッテリー消費量を実測・検証する。

2. **Phase 2: Data Transfer (Watch-to-Phone)**
   * ターゲット: `WCSession` によるWatchからのファイル受信、およびiOS側でのデータ読み込みと基本的な可視化の実装。

3. **Phase 3: Core ML Integration & Visualization (解析・分類)**
   * ターゲット: Create MLによるショット分類モデルの搭載（学習データ収集・アノテーション方針を本フェーズ開始時に定義）、およびiOS側でのダッシュボードUIの構築。
